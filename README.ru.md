# WoTLK Classic HermesProxy Launcher

[English](README.md) | **Русский**

Запускает **WoTLK Classic 3.4.3.54261** для подключения к существующему серверу **AzerothCore 3.3.5a / сборка 12340**. Лаунчер устанавливает закреплённую версию клиента и запускает локальный мост HermesProxy.

| Платформа | Статус |
|---|---|
| macOS Apple Silicon | Проверены авторизация, выбор персонажа и вход в мир |
| macOS Intel | Сборка предусмотрена; работа в игре на Intel не проверена |
| Windows x64 | Экспериментальная реализация; TLS и автоматический вход требуют проверки в игре на Windows |
| Windows ARM64 | Поддержка отложена |

## macOS

Установите Apple Command Line Tools (`xcode-select --install`), затем выполните из каталога репозитория:

```sh
./setup.sh install --server YOUR_SERVER_ADDRESS
./setup.sh remember-account
```

Замените `YOUR_SERVER_ADDRESS` адресом своего сервера. Для игры откройте **World of Warcraft Classic.app**. Вторая команда необязательна: она сохраняет учётную запись сервера в Связке ключей macOS и включает автоматический вход.

Установщик размещает недостающие инструменты в своём служебном каталоге. Для клиента, инструментов и сборок потребуется около **30 ГиБ** свободного места.

| Объект или настройка | Значение по умолчанию |
|---|---|
| Клиент | `~/Games/WotLK Classic` |
| Служебные данные | `~/Library/Application Support/WoTLK Classic Bridge` |
| Лаунчер | `~/Applications/World of Warcraft Classic.app` |
| Язык | `ruRU` (также поддерживается `enUS`) |
| Порт авторизации сервера | `3724` |

```sh
./setup.sh install --server server.example --locale enUS --no-launch
./setup.sh install --server server.example --launcher "/Applications/World of Warcraft Classic.app"
./setup.sh run
./setup.sh check
./setup.sh audit
./setup.sh forget-account
```

Параметр `--target DIRECTORY` задаёт другой каталог клиента, а `--state DIRECTORY` — отдельный каталог служебных данных моста. В последующих командах указывайте тот же `--state`. Параметр `--adopt` позволяет использовать существующий немодифицированный клиент; для уже пропатченного клиента macOS дополнительно нужен `--original-executable FILE` с исходным исполняемым файлом.

Идентификаторы лаунчера macOS, записи Связки ключей и пути установки совместимы с прежним названием проекта `wotlk-classic-macos`.

## Windows x64 — тестовая сборка

Требуются **Python 3.13+**, **Git** и **.NET SDK 10+**, доступные через PATH. Выполните в PowerShell из каталога репозитория:

```powershell
.\setup.ps1 install --experimental --server YOUR_SERVER_ADDRESS --no-launch
.\setup.ps1 remember-account
.\setup.ps1 run
```

Чтобы пропатчить существующий немодифицированный клиент **Windows x64 54261**, добавьте `--adopt --target "D:\Games\WotLK Classic"`. Перед установкой закройте WoW. Установщик создаёт ярлык **Play WotLK Classic.lnk** в каталоге клиента. Служебные данные по умолчанию хранятся в `%LOCALAPPDATA%\WoTLK Classic Bridge`.

Реализация для Windows использует патчер данных для конкретной сборки и небольшой собственный модуль входа на .NET, без зависимости от Arctium. Модуль сохраняет пароль в **Диспетчере учётных данных Windows**, при каждом запуске получает новый билет авторизации Hermes и передаёт его через отдельный раздел реестра лаунчера, зашифровав с помощью DPAPI. Команда `forget-account` удаляет сохранённый пароль.

Эта реализация готова к контролируемой проверке на Windows, но **ещё не проверена в игре**. В частности, нужно проверить принятие сертификата исходным клиентом, начальное значение протокола авторизации (auth seed) и чтение сформированного билета входа. Подробности и порядок проверки: [реализация для Windows](docs/WINDOWS.md) (на английском).

## Как работает запуск

Перед запуском WoW лаунчер запускает мост и локальный сервис метаданных. После выхода из игры он останавливает свои сервисы. Если необходимые порты заняты, запуск прекращается. Сервисы используют порты локального интерфейса **1119, 8081, 8084, 8086 и 8090**. Необработанные данные авторизации и сетевые пакеты в журналы не сохраняются.

На macOS автоматический вход использует модуль TLS и билетов авторизации, работающий внутри процесса клиента. На Windows текущая тестовая реализация оставляет код клиента без изменений и использует сертификат из комплекта Hermes. Установка на обеих платформах не добавляет корневой сертификат в системное хранилище.

Репозиторий содержит исходный код и шаблоны конфигурации. Данные клиента скачиваются с зеркал исторических сборок CASC; доступность загрузки зависит от этих зеркал. HD-модели и текстуры устанавливаются отдельно через [wotlk-classic-hd](https://github.com/Vinges541/wotlk-classic-hd). При `--adopt` лаунчер проверяет и сохраняет совместимый HD-каталог, а metadata-сервис объявляет его активный BuildConfig. [Условия проверки](docs/WINDOWS.md#existing-hd-installations).

## Разработка

Точные коммиты зависимостей и контрольные суммы инструментов указаны в [pins.json](pins.json). Для сборки используются [HermesProxy](https://github.com/Vinges541/HermesProxy), [wow-patcher](https://github.com/wowemulation-dev/wow-patcher), [cascette-py](https://github.com/wowemulation-dev/cascette-py) и вспомогательные модули этого репозитория.

```sh
./setup.sh prepare --state "$PWD/.state"
PYTHONPATH=scripts .state/venv/bin/python -m unittest discover -s tests
```

На Windows команда `setup.ps1 prepare` собирает закреплённые зависимости и модуль входа без установки или запуска игры.

Дополнительная документация на английском: [устройство входа](docs/LOGIN.md) · [TLS на macOS](docs/TLS.md) · [результаты проверок](docs/VALIDATION.md) · [лицензии сторонних компонентов](docs/THIRD_PARTY.md).

Для диагностики Windows: `.\setup.ps1 run --verbose`. После воспроизведения ошибки
закройте WoW и сохраните `%LOCALAPPDATA%\WoTLK Classic Bridge\verbose.jsonl`.
Добавьте `--verbose` также к `install`: в журнал попадут этапы установки, вывод
сборки и ранние ошибки. Новые попытки дописываются без удаления старых; при
`--state` журнал находится в указанном каталоге. Порядок обновления helper и состав безопасного лога:
[диагностика Windows](docs/WINDOWS.md#verbose-diagnostics).

Если новый каталог служебных данных ещё не существует, лаунчер автоматически
использует существующий каталог прежней установки. Её пути и сохранённый вход
сохраняются; данные автоматически не перемещаются. `--state` и `WRATH_STATE`
по-прежнему задают каталог явно. Фактический путь verbose-лога лаунчер выводит
при запуске.
